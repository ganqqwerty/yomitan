R-1 · Optional Japanese grammar wildcards

Match the grammar around the words in between.

A dictionary entry such as せっかく～のに can match a complete phrase such as せっかく早く来たのに. The full-width ～ is a non-empty gap. The feature is off by default.

R-8 · Measured results

The fixed search cost matters more than a few extra rows.

R-9 · The main experiment uses a 22-character input and 314,984 real JMdict term rows in the background. N counts separate pattern records that start with 費用が～. Hover a line or bar for an exact value. Every chart keeps its source table below it.

What N means

R-10 · N is not total dictionary size. It counts rows returned by one matching prefix. One row matches 費用が予想していた金額よりもかなり多くかかる; the other controlled endings fail.

Why N=0 still costs time

R-11 · The enabled lookup builds candidate prefixes and makes 76 extra index requests for this input before it knows that no wildcard row exists.

How to use the numbers

R-12 · Compare absolute milliseconds. A large percentage can describe a small change because the off baseline is short.

R-13 · Engineering view

The implementation reuses existing dictionary indexes.

  1. 1Build text candidatesnormalization and deinflection
  2. 2Collect literal prefixestext before each first ～
  3. 3Read matching rowsexpression and reading indexes
  4. 4Match literal piecesenabled dictionaries only

R-14 · The feature needs no dictionary schema change, full-store scan, generated regular expression, or recursive backtracking. Disabled dictionaries can still cause row reads because dictionary filtering happens after the index returns rows.
